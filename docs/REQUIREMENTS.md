# 拾页 · 需求与推进计划

## 1. 产品目标

让用户用每天 **10–20 分钟** 的轻量节奏读完一本书，并在阅读过程中获得正反馈、连续性和个人化推荐。

## 2. 需求拆解

| 需求 | 实现 |
| --- | --- |
| 用户选书 | 书库搜索、标签筛选、语言筛选、书目详情 |
| 按每日时长切书 | 10 / 15 / 20 分钟可选；中文 420 字/分、英文 220 词/分；按段落/句子收束 |
| 读完当天份量给鼓励语 | 完成弹层展示一句鼓励语、本段字数、用时、阅读日 |
| 想继续可继续提供 | “继续读下一段”按钮；下一段仍是每日份量 |
| 每次读完后询问 | 默认每次完成都弹询问层 |
| 可选择不再询问 | “以后读完自动继续”勾选；阅读页顶部也可随时开关 |
| 记录阅读量和阅读时间 | 完成时写入 `ReadingSession`；累计到 `ReadingProgress`；个人页统计 |
| 书源稳定、数量多 | Project Gutenberg 英文 6 万余本 + 中文公版书 400 余本；正文缓存到数据库 |
| 每本书 3–10 个标签 | 主题/书架映射 + 中文经典人工标签；JSON 存储 |
| 首页阅读推荐 | 新用户热门；老用户按读过的书的标签画像推荐 |
| 用户画像 | 聚合最近阅读的标签权重；个人页展示标签画像 |
| 注册登录、数据不丢 | 邮箱 + 密码；bcrypt；HttpOnly JWT Cookie；Postgres/SQLite 持久化 |
| 蓝白配色、简约高级 | 蓝白设计系统、衬线正文、生成式书封、响应式布局 |
| 英文书中文翻译 | 按阅读段用 DeepSeek 生成，支持原文 / 中英对照 / 只看中译，并缓存译文 |
| 近现代中文作品 | 公版鲁迅作品进入公共书库；《明朝那些事儿》等版权作品通过私人 TXT 导入 |
| 私人书库 | 用户导入自己的 TXT，仅自己可见，不进入公共推荐与搜索 |

## 3. 关键产品决策

- **只提供公版书全文**：不内置现代版权书的全文；后续可加用户导入。
- **书源以古登堡为主**：比维基文库接口更稳定，且同时有中文经典。
- **正文按需缓存**：目录全部入库，正文第一次打开时抓取并写入数据库，节省初始导入时间。
- **“阅读日”按完成段计算**：不是自然日；用户一天内继续读多段，会累计多个阅读日，鼓励持续阅读。
- **自动继续是逐书设置**：用户在阅读器内开关，默认跟随账号偏好。

## 4. 分阶段推进

### Phase 1 · 基础与账号 ✅
- Next.js + Tailwind 蓝白设计系统
- Prisma 数据模型（User / Book / ReadingProgress / ReadingSession）
- 邮箱注册登录、会话、个人页骨架

### Phase 2 · 书库与阅读 ✅
- 古登堡目录导入脚本、标签生成、中文繁转简
- 首页、书库搜索、标签/语言/排序筛选、书目详情
- 每日份量切分、沉浸阅读器、鼓励弹层、继续/自动继续、阅读计时

### Phase 3 · 推荐与画像 ✅
- 热门推荐（下载排名 + 中文经典加权）
- 标签画像推荐、推荐理由、个人页画像、连续天数

### Phase 4 · 上线准备（进行中）
- Vercel + Neon 配置、迁移、`vercel-build`
- 生产环境种子数据与正文预取
- 邮箱验证/找回密码（后续）

### Phase 5 · 增强（后续）
- 用户导入 TXT/EPUB
- 阅读日历、周报、目标提醒
- 笔记、划线、收藏
- 更细的标签与协同过滤

## 6. 仍需确认 / 输入

1. **DeepSeek API Key**：英文中译需要 `DEEPSEEK_API_KEY`；未配置时页面会提示未启用。
2. **正式书名**：当前工作名为「拾页」，可以改。
3. **更多公版近现代中文书源**：老舍、萧红等作品在部分书源中不可得，需要确认可用的公版文本来源。
4. **EPUB 导入**：当前先支持 TXT，EPUB 需要继续接入解析依赖。
